## 影响结果有效性的原稿问题

1. **数据来源错误**：原 `my_report/data/Electricity_16ch.npy` 和 `Solar_16ch.npy` 与 `src/data_loader.py` 的 `generate_benchmark_synthetic_data(config, seed=42)` 逐元素完全相同。原缓存 SHA256 分别为 `735bbf45373c319aa345c44dd589a7d4071de988da36b70d4113328fa892d388` 和 `aed371c8bc83775b69a95254c9888521331d625d9cd23299e0b2d9b1439b1037`。这些是本地人造信号，不是 Monash 发布数据。不能因为数组长度正确就视为正式数据。
2. **静默降级**：原加载器下载/解析失败时自动生成合成数据，并复用与正式数据相同的缓存名。新版取消此行为：正式发布 ZIP→TSF→逐 ID 选择→独立复现分层选择→SHA256 manifest→校验后读取；缺失或哈希不一致明确报错。
3. **硬件表述混淆**：原数据库主实验记录 `device=cpu`；`section8_profiling.py` 却把训练图标题写作 Colab T4。旧延迟 JSON 则记录 RTX 3060 Laptop GPU。新版仅写实际测量设备，不将理论 T4 估算称为实测。
4. **模型复用表述不实**：现有 DLinear/PatchTST 是自写类，未直接导入 Time-Series-Library，也没有可核实的上游代码 commit。新版明确 DLinear 为自写实现、PatchTST 为简化风格模型，不宣称原模型精确复现或官方基准成绩。保留设计机制，但解释归一化、位置编码与训练细节的局限。
5. **实验身份与 checkpoint 覆盖**：旧敏感性训练采用同名 checkpoint，可能覆盖主实验。旧数据库还混有重复运行和不同 epoch 预算。新版每次运行有唯一 ID 和独立目录，保存配置、scaler、起点、完整预测、最佳权重、数据哈希、环境、曲线和 SQLite JSON。
6. **配置与实现不一致**：旧 DataLoader 固定 batch=32，不读取训练配置；验证损失按 batch 简单平均；新版 batch 可配置，验证 MSE 按元素计数加权，不使最后一个小 batch 获得过大权重。
7. **单位与统计结论**：未独立确认发布版本物理单位时不标 kW/MW。不把标准化训练损失当作原尺度 MAE；不混淆通道平均 MASE 和整体 MAE 的不同权重。不把单次最好种子视为均值；不对高度重叠窗口做独立样本显著性宣称。
8. **身份占位**：旧英文稿中的 100001/100002 为虚构占位，删除。按用户确认保留可见待填写字段。

## 新实验执行协议与迭代过程

先以seed42完成正式数据初步检查，随后按大纲补固定seed43/44与两类敏感性。追加过程没有根据测试排名更换通道、模型结构、学习率或挑选最好种子。不是所有追加运行都早于第一次查看新版测试结果，因此不将此次测试区间描述为盲测。

- 初步预算：主实验六个可训练模型各最多 5 epochs，patience=3，学习率 0.001，Adam，weight decay=0.0001，batch=32；三个固定种子 42、43、44。两个无训练基线确定性相同，重复记录只用于接口一致性，不算独立随机试验。
- 两个数据集分别训练，冻结 16 通道、70/10/20 时间分割、训练 stride=3h、验证/测试 stride=1h，所有模型相同起点。各通道训练区间拟合 scaler。
- 窗口敏感性：24h、48h、168h；共同训练起点按 168h 历史确定；LSTM/PatchTST-style，seed42，最多5epochs。
- 数据量敏感性：原训练区间末尾25%、50%、100%；scaler 在各可用片段拟合；验证/测试保持不变；LSTM/PatchTST-style，seed42，最多5epochs。
- 测试集已在历史稿被查看，新运行不根据新版测试误差调参、换子集、选最好seed。现有测试区间仍不能称为完全未触碰的外部盲测集。
- 终稿计划：验证集限定调参、最多20epochs，敏感性多种子，补容量匹配消融、失败案例、必要时独立后续时间段验证。未做的内容明确作为计划。
